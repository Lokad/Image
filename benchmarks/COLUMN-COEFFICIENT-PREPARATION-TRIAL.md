# Column coefficient preparation trial

Two output-backed horizontal coefficient preparation layouts are **not retained**.
Both preserve exact samples and ownership but show no useful complete-operation
gain. Original production sources, Windows/Linux DLLs and the actual development
package are restored exactly. Current costs remain in
[adjacent resize confidence](RESIZE-CURRENT-ADJACENT-CONFIDENCE.md).

Each screen retains all three actuals, frozen inputs/settings, original rational/
exact managed samples, approved native bounds, independent output, source and
quiet-VM gates. These are adverse screens, not independently confirmed causal
regressions. Neither justifies confirmation, broader tuning or package work.
No repeat is taken to seek favorable bounds. This rejects these implementations,
without closing preparation/reuse or materially revised designs as a family.

A prepares eight exact wide coefficients per eligible pair once per strip and
shares the existing 16-column shape. Its unpublished output loan falls from
11,776 to 9,984 B and fixed local payload from 3,424 to 1,952 B; the reservation
stays 4 KiB. B keeps the useful 32-column shape, borrowing 19,968 B when available
and retaining the original packed-weight loan for smaller results. On the frozen
256×129 result, its larger loan moves tail work from row 117 to 109. Every
borrower retires before tail geometry rebuild and pixel publication. Owned image
capacity, pools, admission and retained scratch remain unchanged; physical/native/
JIT peaks are unmeasured. Allocation reductions are not claimed.

B's initial bounds test catches reduced small-result eligibility before timing.
The corrected version preserves those original paths. Failed preflight sources,
modules and logs remain. A passes 571 internal / 791 public focused checks and B
572 / 791 per normal/scalar mode on each OS, including all three named storage
suites, coefficient-bit oracles, poisoned phase boundaries, low alpha, refusal,
cancellation cleanup and surviving outputs. Prototype-only helpers/tests are
removed on restoration.

Both actual shared Resize callers remain exactly 9,388 code bytes after only
address/method-number normalization. The row-loan body grows 6,612→7,152/7,529 B;
even the unexpanded tail grows 6,528→7,057 B. These code-generation diagnostics
do not assign phase costs or establish the cause of elapsed differences. Next
inspect compact paired coefficient loading that avoids additional live preparation
state, larger output loans and extra tail work; require exact ordered bits and
complete-operation evidence before acceptance.

One useful original-kernel test remains: minimum-height 513×43→256×21 RGBA8
checks exact oracle pixels, poisoned tail storage, cancellation, shared-budget
cleanup, immutable source and surviving output. Windows/Linux each pass 3,183 full

exercises the fast path. Gated early returns are not claimed as scalar coverage.
No core rebuild follows restoration; each embedded test assembly is rebuilt once
for the retained test. Across prototypes/restoration, Windows has three core/four
embedded builds and Linux two/three; public/harness/native/fixtures are reused.
There is no package or broad public/live qualification repeat.
