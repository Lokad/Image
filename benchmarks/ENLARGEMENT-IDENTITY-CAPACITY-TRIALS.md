# Enlargement identity-height capacity trials

Neither implementation is retained. Production sources and actual package are
restored byte for byte; the eight useful rational/ownership tests remain.
This is an **inconclusive performance hypothesis**, not a proven regression or
a permanent ban on materially different scheduling designs.

The shared schedule already reduces cardinal identity-height filtering to one
unit tap. Candidate A reduced cached capacity to one row, shrinking the borrowed
output view 254,680→123,224 B and explicit stack arrays 4,000→2,144 B. Candidate B
kept the original fixed 4,000 B stack frame and only changed the borrowed view.
Both retain a 4 KiB scratch allowance, independently owned output and original exact math.
The view reduction does not reduce owned result capacity or actual admission.
Logical source-decoding counts predict less repeated work; they do not prove
an elapsed-time benefit.

Four existing three-actual screens per variant covered byte/word horizontal and
full enlargement; all pixel/resource/reference gates passed. A's byte point was
1,642.20/native 1,516.49 µs; B's 1,628.15/native 1,649.30 µs mixed slower raw time
with a better normalized point. Screens are diagnostic, not parity evidence.
One independent primary confirmation and one adjacent frozen predecessor resolve
that uncertainty without a twelve-case qualification campaign:

B saves 37.47 µs/2.23% raw with separated filtered/all-actual intervals, but native
time falls 42.53 µs/2.59%. Normalized points worsen 0.37% with overlapping intervals;
no useful incremental benefit is established. B is uncertain, not a parity pass.
No subject is repeated merely for favorable numbers. No claim depends on
summing historical stages, a fixed continuation threshold or lower-memory retry.

Read-only sampling on the restored actual DLL reuses the prepared harness, with
zero builds: 1,997 CPU-clock samples, 1,992 mapped to managed methods. Exclusive
shares are WriteRow 44.97%, FilterHorizontal 30.95%, ReplayTiny 9.16%, DecodeRow 3.61%
and PrepareHorizontal 1.55%. Sampling/JIT inlining do not establish elapsed phase
costs, and instrumented timings are not current performance proof. Original pixel,
native, source/owner and idle-v2 gates still pass. The collector uses CPU1; the
complete managed operation remains on CPU0.
