A uses one borrowed high-aligned reservoir and one actual coefficient kernel for
standalone/shared execution. B extends its lifetime through eligible ordinary scan
blocks, publishing before scalar fallback, restart and scan completion. B also
vector-finds the next FF byte and memoizes its range: a zero-copy span ending
there makes the original four-byte bounds test sufficient for stuffing-free
refills. Scalar stuffing/marker handling remains. No unescaped-input copy,
additional table, heap buffer, owner, pool, session or retained storage is added.

The 32-byte borrowed window and B's two scalar bounds fit the existing coarse
1,024-byte parser allowance. Admission, owned storage and cleanup statements are
unchanged; physical/admitted/native peaks were not remeasured. New DC continuation
requires 19 bits before validating its short prefix/amplitude. Rejection preserves
the completed prefix, and scalar continuation never replays consumed coefficients.
Live tokens cannot open the shared window and retain every existing checkpoint.

then **411 / 375** for B. Tests compare actual shared execution with an independent
scalar grammar across cached phases, multi-block windows, categories, long codes,

expected an unnecessary byte fetch for an already cached short code. Its source,
failed embedded module and log are retained; only the test was corrected and its
embedded assembly rebuilt. The production DLL was reused unchanged.

Original RGB444 and sparse Adobe CMYK inputs/settings, exact independently owned
