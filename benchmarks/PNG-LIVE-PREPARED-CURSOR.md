# Prepared live PNG cursor

[Prepared live-run invariants](PNG-LIVE-RUN-PREPARATION.md) supersede the two
live costs below. Earlier exact traversal/profile evidence and raw archives remain
history and motivation, not current affected timing proof.

PLK571 holds a materialized live block's cache, bit count and input offset locally.
It reuses the existing prepared ten-bit table when full maximum-depth lookahead
is already cached. Unknown/refill/deeper prefixes keep the canonical helper.
Literal runs, per-field cancellation checks and match copying remain unchanged.
The replaced live loop is removed; no forwarding API, array, pool or session is
added. Ordinary, rolling-history and counting paths retain their existing bodies.

Independent complete operations verify these scoped gains against source-valid
qualified-original confirmations, reused with frozen inputs/workers/settings:

- RGBA8: **1,539.10 → 1,391.93 µs**, saving **147.18 µs / 9.56% raw / 9.54%
  reference-normalized**.
- RGBA16: **2,950.95 → 2,919.94 µs**, saving **31.01 µs / 1.05% raw / 1.04%
  normalized**.

Filtered/all-actual raw and normalized confidence separates for both. Native
points move −0.020%/−0.016%. These claims cover the two frozen live-token
513×259 RGBA controls, with exact pixels, alpha and hidden RGB. They establish
neither general decoder gains nor parity.

Both sides include complete decoding, normalization, independent output ownership

The first local-state prototype screens at 1,657.39 µs and is unpromising.
Generated code gives its four exception regions a 152-byte reported local frame
and stack-held cache state. A second stage publishes only at normal completion:
the sole production caller owns and discards the private reader on failure.
Outer framing/codec cleanup, exact public errors, partial stores and cancellation
polls remain. Its 1,452.00 µs screen motivates reusing already-known ten-bit
prefixes locally. No gain is inferred from code size or eligibility alone.

An independent RFC1951 refill model matches every filtered byte against zlib.
Of 24,024 ten-bit codes, 20,305 already have full maximum-depth lookahead; the
other 3,719 retain the original helper. The direct branch preserves the original
maximum Peek and Consume checkpoints. It adds no speculative reads or padding.
Incomplete codes, tails and reserved/error cases retain their original ordering.

public** per normal/scalar mode. The same actual Release package/all three examples
pass both OSes. Consumers exercise exact byte/word sync/async samples, borrowed
streams, aggregate admission, terminal refusal/recovery and independent survivors.
The unchanged root/context succeeds with a fresh reader after a truncated live
block; failed private bit state is not a public or resumable output.

The short worker hardcodes RGBA8. An attempted word screen is rejected by the
