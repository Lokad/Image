# Bicubic tail geometry experiment

The operation-owned geometry prototype is **unselected**. It removes repeated
preparation, but two complete short comparisons do not establish a useful elapsed
gain for its added alias-lifetime complexity. The qualified production sources,
main/embedded assemblies, source manifests and cached bindings are restored byte
for byte on Windows/Linux. Existing correctness and actual-package proof remains
valid; no full-suite or package replay.

All frozen pixels, source/independent ownership, native bounds and quiet guards pass.

The prototype prepares 31 tail rows as 56-byte records in 1,736 bytes already owned
by the final output row. It retires those views before overlapping tiles and uses
the original helper thereafter: 2,782→1,046 source-level vertical preparations.
No added allocation, cache, session or admission; required 4,264,104-byte output,
4,000-byte stack and 4 KiB workspace bound stay unchanged. Counts are not CPU proof.
Physical/native peaks are not newly measured. Cancellation, refusal, tiny-alpha
repair and independent survivors pass 61 internal/571 public focused checks per
normal/scalar mode on each OS. Candidate-only tests are retained with the raw study.

A single current two-second profile of the restored `TightUp16` operation has
1,977 samples: word-row filtering/certified publication 73.4%, horizontal filtering
16.4%, exact repair 3.0%, decoding 1.3%, vertical preparation 1.1%. This explains
the limited geometry opportunity and directs the next investigation toward the
dominant publication/filter pipeline. Method self-samples include inlined work;
they are attribution, not phase elapsed times or instruction-level stall proof.
The cached profile driver/harness/reference require no build.

Managed complete public Resize includes preparation, admission, materialization,
independent output and disposal. The labeled zimg 3.0.6 reference retains its graph,
input workspace and scratch outside timing, while halo/conversion/filtering/output/
quantization remain timed. This preserves the existing repeated-reference boundary,
not one-shot preparation parity. Exact rational/qualified-half managed results and
native-only float bounds are unchanged.
