# VP8 invariant preparation and compact storage

The completed prototype removes repeated invariant-price generation and saves
6,624 allocated bytes per encode, but independently slows the actual trellis
workload. Restore the qualified implementation. A counterbalanced build comparison
points the other way; it does not override the complete standalone boundary.

Every rate owner currently derives 256 entropy, 2,048 fixed-level and 1,008 mode prices,
then stores 3,312 invariant words alongside 6,720 model-dependent words. The experiment
independently generates read-only module data from the existing integer policies
and repository format constants. It imports no upstream implementation table and
adds no runtime heap cache, pool, production dependency or external build input.
Existing current profile locations motivate the audit, not projected phase savings.

The first stage copies that module data into the unchanged admitted arena, isolating
derivation removal. Its complete short screens are inconclusive: trellis+0.72%,
photograph+0.07%raw, unchanged allocation. The completed stage removes the redundant
prefix and passes separate fixed/variable views into the existing residual kernels.
